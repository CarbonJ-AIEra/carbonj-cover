# carbonj-cover · Agent 自主执行模式（SOP）

这是 carbonj-cover 的 Agent 自主执行轨道：不使用 `generate_carbonj_cover.py` 做选帧、分析或生图，不需要外部 Gemini 和 ZenMux key。执行 Agent 用自身多模态能力选帧、分析，并用参考图生图工具独立生成每个画幅的完整最终封面。

## 何时使用

- 用户明确要求自主模式、不要脚本，或要求 Codex 直接执行。
- 当前环境缺少脚本依赖或 ZenMux key，但具备多模态视觉与图生图能力。

否则使用脚本模式。

## 前提与规则来源

执行 Agent 必须具备多模态视觉和支持参考图的生图工具。在 Codex 中使用 `.system/imagegen` 的 `image_gen` 工具；先用 `view_image` 将选中的真实屏幕帧和产品 Logo 加载进上下文，再在 prompt 中引用。

开跑前必须完整阅读 `references/cover-rules.md`。本 SOP 只描述执行过程，视觉判断以该文件为准。

## 产物目录

- 在视频或截图同目录创建 `<文件名>.carbonj-cover/`。
- 其中保留 `frames/`、`analysis.md`、`cover_plan.md`、六份 `.prompt.md`、六张 `<画幅>.generated-base.png` 与生成记录。
- 最终图写回输入同目录：`<文件名>_3x4.png`、`_4x3.png`、`_16x9.png`、`_2.35x1.png`、`_youtube_16x9.png`、`_youtube_9x16.png`。

## 执行步骤

### 0. 确认标题

标题确认前，不得取帧、调用图像工具或写最终图片。用户未提供标题时，根据字幕/文稿和视频主题给出 5 个有钩子的候选；用户已给标题时只询问是否确认。确认后，标题不得在后续流程被擅自改写。

### 1. 建工作目录与选帧

- 视频先抽取 4–8 张候选帧，逐张按 `cover-rules.md` 选择真实、清晰、最能说明主题的一帧，再抽取该时刻全分辨率版本。
- 截图或关键帧输入直接使用。
- 在 `analysis.md` 记录选中的画面和原因。没有合适实操画面时说明缺口并请用户决定，不要硬凑。

### 2. 分析内容与匹配 Logo

在 `analysis.md` 明确主主题、主产品、承载界面、一眼主语、主/辅助证据和可牺牲信息。读取 `product-assets.md` 和 `assets/product-logos/`；存在可信 Logo 时作为参考图，否则以真实截图中的产品识别为准。

### 3. 写方案与独立提示词

- 在 `cover_plan.md` 写六个画幅的标题断行、构图、证据和 Logo 位置。
- 分别写 `3x4`、`4x3`、`16x9`、`2.35x1`、YouTube `16x9` 和 YouTube Shorts `9x16` 的完整 prompt sidecar。
- 每一版必须是独立设计：明确精确比例、真实证据提炼方案、标题层级、背景、主证据与删除项。不得裁切或复制另一画幅充数。
- 所有版本必须是完整纯图封面：不要人物、人脸、头像、摄像头气泡、真人画中画、吉祥物或角色。
- 写完 sidecar 才可调用生图工具。

### 4. 生成并写入最终图

- 真实屏幕帧和 Logo 仅作参考，不做整张复刻。
- 每个画幅单独调用一次。可并发时并发生成，但要核对数量、命名与尺寸，缺少版本立即单独重跑。
- 生成的图片直接保存为最终文件和 `.generated-base.png`；禁止任何本地合成、贴图、裁切、重排或视觉修补。

### 5. 质检与收尾

逐张检查：标题可读、产品识别可信、主证据够大、无完整截图噪音、无人物元素、无固定顶栏，且平台比例正确。失败时只重跑失败的单一画幅和对应 prompt。

确认输入同目录存在全部目标图片，工作目录存在分析、方案、六份 prompt、生成记录和无人物底图。

## 不可违反

- 不要在生图后本地贴字、贴 Logo、拼接、裁切、重排或视觉修补。
- 不得在任何画幅出现人物、人脸、头像、摄像头气泡、真人画中画、吉祥物或角色。
- 默认不加固定顶部 Panel、品牌字标、顶栏或横线，除非用户单次明确要求。
- 只使用当前视频、标题、字幕、截图、Logo 和用户补充信息，绝不带入历史任务内容。
- 每次生图前保存 prompt，完成后保留 `analysis.md`、`cover_plan.md`、prompt、生成记录与最终图；文档只描述当前最终状态。
